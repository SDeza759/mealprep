## Data Flow (solver)
Targets + meals/day → sample 100 combos/day → loose pre-filter → softmax rank → solver-as-filter over the
top 10: first in-zone ([95%,105%] all 4 macros) solve with meal spread ≤1.35, else most balanced in-zone,
else shake-planned in-zone, else least-bad + deficit shake.

  Home logs (eaten marks, any day of the week); Fuel edits (swap/add/remove). No settings button on Home.
  Grouped days shift to lifting-day targets only when every day in the group lifts. Local-first, no

## Key Decisions (don't reverse)
- **Core files stay classic scripts, loaded before the bundle.** Never `import '../data.js'`; go through
  `app/src/core/index.js`. Converting the core to ESM later touches that file + the harness only.
- **Combo-first, solver-as-filter, dynamic feasibility**: whole-day combos; the gradient solver IS the
  feasibility check (≤10 combos/day); only the [95,105] zone is fixed.
- **Meals/day is the user's call**: `generatePlan` 9th arg `mealCounts` overrides the heuristic; the UI
  passes a DENSE 7-day map (`resolvedMealCounts`); the harness omits it. Set per unit (group or single day).
- **Registry is single source**: recipes are `{name,grams}`; never inline macros.
- **Unified pool** (any recipe, any slot). **Variants**: only Shawarma Bowl; `selectVariant` is
  variants-only, module-scope and exported — never add 1-variant recipes.
- **Per-recipe spices** (`RECIPE_SPICE_OVERRIDES`); no cuisine-default system. **No cuisine cap.**
- **Swap picker is an unranked list** (favorites first, A–Z, searchable); the day re-solves after the pick
  and a toast reports out-of-zone. No pre-filtering/dry run (the S4 false-negative bug).
- **Regenerate is per unit**: a day regenerates with its whole current group (`regenerateDays` expands the
  selection, seeds kept recipes, refreshes `plan.groups` for those days). No multi-select checkboxes.
- **Manual edits are group-aware** (computed once from the interacted day, cloned to `planGroupMembers`),
  EXCEPT servings and eaten marks, which are per day. Batch/fresh tags are group-aware. Servings feed only
  the grocery list and Cook Day portions.
- **Meal balance is a preference** (spread ≤1.35), never a hard constraint. 6 meals at 2000cal fails ~96% — expected.
- **Shake-aware solving, shakes rare**: shakeless in-zone → planned shake → least-bad + deficit shake.
  `computeDay` in `planOps.js` adds the shake once; a removed shake sets `day.noShake` until regeneration.
  The shake's eaten slot is index `meals.length`.
- **Manual re-solves anchor at recipe grams** (`baseMealIngredients`), never at the previous solution.
- **Generation is a rolling window, never "the week"**: Generate starts on the selected day (today by default)
  for N days (`settings.planDays`, default 7, up to 28; stepper inline on the empty-day card and on Grocery) and
  maps onto the week documents it touches (`regenerateDays` with `expand:false`; recipes used earlier in the
  window seed later weeks). Replacing days that already hold meals asks first (`Confirm` in `Fuel.jsx`). A group
  only partly inside the window plans just its in-window days. "Repeat last plan" copies, per weekday, the most
  recent earlier day with meals. Storage stays per week, keyed by Monday (`plans.weeks`), a year back or ahead.
- **Review as a new user**: `?fresh` on any URL (`FreshStart` in `App.jsx`) asks, erases everything and reloads as a
  first launch — same as More › Backup › Erase everything. A private window is the zero-setup alternative.
- **No intermediate sheets for things a screen already shows** (user's call): generation is inline on Fuel, no
  form. **Home stays simple**: the day, what's left, meals with an Eaten switch, and one "Meal Plan" link to Fuel.
- **Group identity is scoped by generation batch**: `groups[di] = {groupIndex, gen}`; `planGroupMembers` only
  joins days with the same `gen`, so a window starting Tuesday never drags Monday's older plan along.
- Day groups, free days and cook days are weekday patterns applied to whatever gets generated. Saved plans
  snapshot/load the calendar week being viewed. Logging eaten meals sweeps every week's ticks into one entry.
  Grocery is the rolling window from the selected day (`planDays` long); check-offs live on `plans.groceryChecked`.
- **Cook Day = a unit's batch meals × servings, merged** (ingredients summed, steps in recipe order, timers
  parsed from step text, portion chips per day). Meals default to batch; `fresh` opts out.
- **Units setting** (lb·oz / kg·g) changes grocery + cook amounts only; recipe tables stay grams.
- **Notifications are stored toggles only** until the Capacitor app; master switch off by default.
- **Hosting: GitHub Pages via `pages.yml`** (already wired, free, same origin as the old app so its
  localStorage migrates on first launch). Cloudflare Pages is the upgrade for a custom domain.
  Base path = repo name; deep links work through `404.html`.
- **Peruvian recipes are research-backed**; don't genericize. All 139 were held to that bar.
- **Harness resets `state` ONCE** before the week loop. **All randomness via `rng()`**.
- **Grocery shows store-scale units** (decimal lbs + oz); **counts are eggs only**; no produce counts.
- **Citrus is juice + zest** (`Lime Juice`/`Lemon Juice`; `Lemon Zest` spice; no `Lime Zest` until needed).
- **Macro audit rows**: 16 registry rows carry retail-label values, each with a `// S20 macro audit`
  comment naming brand + old USDA value; `Bacon` = USDA raw (never re-base on a cooked label); dry-bean
  names `… (Dry)` with steps that cook from dry; `Edamame (frozen)`; `Cherries (frozen)`; `Tofu` stays USDA.

## Fragile Areas
- `state` in algorithm.js is a global `const`: readable by bare name, NOT `globalThis.state` (core/index.js does this).
- `useDoc(key, fallback)` needs a referentially stable fallback (see `defaults.js`) or it re-renders forever.
  `setDoc(fn)` updaters run synchronously — `usePlanActions` relies on that to capture zone results for toasts.
- Recipe `name` must match a registry key exactly or macros silently zero. Two ground-beef rows.
- Combo fallback + one 3-meal retry (gated on `!userCount`): removing either risks loops/catastrophic days.
- Solver bounds [0.5,3.0] are mirrored in `comboFeasible`. Carb floor ×4 below 88% (80% if protein binds).
  Eggs snap to 50g; binder eggs capped at original grams. `isBreakfast` via `tags`, not meal index.
- Pre-filter is deliberately loose (tightening once regressed to 91.9%). Run the validator after touching it.
- Mutate module `state` in place, never rebind. Never map "code broke" onto a domain value (S4 `catch` = 99).
- `plan.days` is dense with nulls; empty days are valid and skipped by averages. Plans/favorites are keyed
  by recipe name and go stale on renames until regenerated. The macro-audit build fails if a record name
  is missing from the registry (rename records after any registry rename).
- `.week`/`.day` classes are shared by the Fuel strip and Settings › Days. Sheets are bottom sheets under
  900px, centred modals above; `useIsDesktop()` is the breakpoint hook.
- Legacy `index.html`: `.wk-narrow` is measured (ResizeObserver), never `display:flex` on `.wk-meal-cell`;
  frame/overflow live on `.wk-table-scroll`; its export carries daygroups/favorites/overrides (Dialed imports it).
- Lessons: re-derive counts yourself (reviewer claims were wrong); prove a generator round-trips
  byte-for-byte before extending it; measure base-vs-solved before blaming selection; an "adjust" tick
  contradicting a label's form means re-base on the right form, not copy the label; the Browser pane can
  hide mid-session — drive checks with `javascript_tool` + `read_page`, keep screenshots for the end.

## Conventions
- New ingredient: registry (USDA raw/100g, or a sourced label with a comment) + `INGREDIENT_CATEGORIES`
  (+ `MEAT_INGREDIENTS` in `app/src/core/display.js` if flesh meat). New recipe: `RECIPES` + spices
  (savory ≥ Salt + Black Pepper) + `RECIPE_COOKING_DATA` (no numbered steps; name every non-spice
  ingredient; no phantoms). Aim ≥5 recipes/ingredient.
- Zero-macro seasonings live in `RECIPE_SPICE_OVERRIDES` — but `White Wine`, `Mirin`, `Dry Sherry`, `Sugar`,
  `Worcestershire Sauce`, `Parsley` are registry rows; filing one as a spice discards calories.
- Cooking liquid goes in step text, proportional to grams; never a `Water` ingredient.
- canAdjust: ≥50 cal, not spice, not soy sauce; unit items fixed. Shake 25P/3C/1F/120cal, 1/day.
- UI: tokens only (`var(--…)`), `.num` for numbers (Barlow Condensed), `.eyebrow` labels, fixed macro
  colours always text-labelled, inline SVG icons, ≥44px touch targets. Every manual-edit path goes through
  `planOps` then `setPlanDoc`; never solve inside a component.
