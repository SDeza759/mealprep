## Data Flow
Targets + meals/day → sample 100 combos/day → loose pre-filter → softmax rank → solver-as-filter over the
top 10: first in-zone ([95%,105%] all 4 macros) solve with meal spread ≤1.35, else most balanced in-zone,
else shake-planned in-zone, else least-bad + deficit shake.

## Key Decisions (don't reverse)
- **Combo-first, solver-as-filter, dynamic feasibility**: whole-day combos; the gradient solver IS the
  feasibility check (≤10 combos/day); only the [95,105] zone is fixed.
- **Meals/day is the user's call**: `generatePlan` 9th arg `mealCounts` overrides the heuristic; the UI
  must pass a DENSE 7-day map (`resolvedMealCounts()`); the harness omits it.
- **Registry is single source**: recipes are `{name,grams}`; never inline macros.
- **Unified pool** (any recipe, any slot). **Variants**: only Shawarma Bowl; `selectVariant` is
  variants-only, module-scope and exported — never add 1-variant recipes.
- **Per-recipe spices** (`RECIPE_SPICE_OVERRIDES`); no cuisine-default system. **No cuisine cap.**
- **Swap picker is an unranked list** (favorites first, A–Z, searchable); the day re-solves after the pick
  and `swapWarning` reports out-of-zone. No pre-filtering/dry run (that was the S4 false-negative bug).
- **Partial regen**: `excludedDays` + optional `seed` ({recipeNames}); grouped days reroll as a unit.
- **Manual edits are group-aware** (computed once, cloned to `planGroupMembers(di)`), EXCEPT the serving
  stepper and the eaten checkbox, which are per-day. Servings feed only the grocery list.
- **Meal balance is a preference**: one extra even-share solve + early-accept at spread ≤`BALANCED_SPREAD`
  (1.35); never a hard constraint (costs solve rate). 6 meals at 2000cal fails ~96% — expected, not a bug.
- **Shake-aware solving, shakes rare**: (1) shakeless in-zone, (2) `planShake` solve against
  targets-minus-shake, (3) least-bad + deficit shake. `solveDayShakeAware` (manual edits) returns meals-only
  totals and index.html adds the shake once; `trySolveCombo(planShake)` counts it in — don't unify blindly.
- **Shake removable per day** (`handleRemoveShake` sets `day.noShake`; regenerating clears it).
- **Manual re-solves anchor at recipe grams** (`baseMealIngredients`), never at the previous solution.
- **Peruvian recipes are research-backed**; don't genericize. All 139 were held to that bar.
- **Harness resets `state` ONCE** before the week loop. **All randomness via `rng()`**; `setRandomSeed(n)`
  / `--seed=N` replays a week.
- **Grocery shows store-scale units** (decimal lbs + oz, no grams); **counts are eggs only**; no produce counts.
- **Citrus is juice + zest** (`Lime Juice`/`Lemon Juice`; `Lemon Zest` spice; no `Lime Zest` until needed).
- **Macro audit decisions applied (S20)**: 16 rows carry retail-label values (each with a `// S20 macro
  audit` comment naming brand + old USDA); `Bacon` = USDA raw (never re-base on a cooked label);
  bought-form names `Black Beans (Dry)`, `Chickpeas (Dry)`, `White Beans (Dry)`, `Kidney Beans (Dry)`,
  `Edamame (frozen)` with steps that cook from dry; `Cherries (frozen)` replaces the duck's jarred sauce.
  `Tofu` stays USDA by the user's choice.

## Fragile Areas
- Recipe `name` must match a registry key exactly or macros silently zero. Two ground-beef rows.
- Combo fallback + one 3-meal retry (gated on `!userCount`): removing either risks loops/catastrophic days.
- Solver bounds [0.5,3.0] are mirrored in `comboFeasible`. Carb floor ×4 below 88% (80% if protein binds).
  Eggs snap to 50g; binder eggs capped at original grams. `isBreakfast` via `tags`, not meal index.
- Pre-filter is deliberately loose (tightening once regressed to 91.9%). Run the validator after touching it.
- Mutate module `state` in place, never rebind. Never map "code broke" onto a domain value (S4 `catch` = 99).
- Add-meal rides the swap modal (`isAdd`, `mealIdx = meals.length`). Every manual-edit path re-solves via
  `solveDayShakeAware` then applies the shake once. Remove clears `eatenMeals`/`mealServings`; add doesn't.
- `plan` is SPARSE (`new Array(7)`; `map` skips holes): build with `Array.from({length:7})`; saved plans
  hold nulls. Empty days are valid and skipped by averages.
- Plans and favorites are keyed by name and go stale on renames (S15, S19, S20) until regenerated.
- Weekly table: `.wk-narrow` is measured (ResizeObserver), not a media query; never `display:flex` on
  `.wk-meal-cell`; frame/overflow live on `.wk-table-scroll`; `.wk-name-row` reserves 56px for the stepper.

## Conventions
- New ingredient: registry (USDA raw/100g, or a sourced label with a comment) + `INGREDIENT_CATEGORIES`
  (+ `MEAT_INGREDIENTS` if flesh meat). New recipe: `RECIPES` + spices (savory ≥ Salt + Black Pepper) +
  `RECIPE_COOKING_DATA` (no numbered steps; name every non-spice ingredient; no phantoms). Aim ≥5 recipes/ingredient.
- Zero-macro seasonings live in `RECIPE_SPICE_OVERRIDES` — but `White Wine`, `Mirin`, `Dry Sherry`, `Sugar`,
  `Worcestershire Sauce`, `Parsley` are registry rows; filing one as a spice discards calories.
- Cooking liquid goes in step text, proportional to grams; never a `Water` ingredient.
- canAdjust: ≥50 cal, not spice, not soy sauce; unit items fixed. Shake 25P/3C/1F/120cal, 1/day.
- localStorage keys: `mealprep_daygroups` ({groups, excluded, mealCounts}), `mealprep_plans`,
  `mealprep_overrides`, `mealprep_stats`, `mealprep_stats_last_view`, `mealprep_favorites`.
- **Gate before calling any data/algorithm change done**: `node tests/run.js validator` (700/700),
  `simulator` (7000/7000, 139/139), `node audit/cuisine-audit/phase-b/hygiene.js`. Verify UI in the browser.
